# 交互框架说明（v2.9.0）

这份文档记录 v2.9.0 交互重构的**设计依据**与**具体落地**：每条能力先写主流 ChatAI / Agent 客户的通行做法，
再写本插件在内核受限（Chromium 59）条件下的实现方式。改动交互前请先读「兼容红线」一节。

---

## 1. 设计参照

主流产品（ChatGPT / Claude / Gemini / Cursor / Copilot Chat / 各类本地 Agent 客户端）在交互上高度趋同，
归纳为 7 条共识。本插件按这 7 条重构：

| # | 共识做法 | 本插件落地 |
|---|---------|-----------|
| 1 | 会话是一等公民：常驻侧栏、新建/搜索/切换/重命名/删除 | 左侧常驻会话栏（158px），支持搜索、双击改名、删除、折叠 |
| 2 | 会话绑定上下文来源，换文件就换上下文 | 一个 md 文件 = 一段对话（`autoDocSession`），切文件自动切会话 |
| 3 | 流式期间可自由阅读，不被强制拽到底部 | 滚动锚定 + 「回到底部」浮标 |
| 4 | 随时可停，停了不丢已生成内容 | `Esc` / 停止按钮 → 保留半成品，标记「已停止」，可继续 |
| 5 | 每条回答都可再操作：复制 / 重新生成 / 编辑重发 | 消息操作条（悬停出现） |
| 6 | Agent 执行过程可见可干预：计划卡、步骤折叠、停止 | 计划 → 步骤卡 → 工具调用可折叠，停止后断点续跑 |
| 7 | 键盘优先：发送、停止、开关面板都有快捷键 | 见第 6 节 |

---

## 2. 会话与文档绑定

早期版本的致命体验问题：换了 md 文件后仍在用上一篇的上下文回答，模型答得一本正经但答的是别的文件。

现在的规则（`plugin/client.js` 的 `docKey / checkDocChange / applyDocChange`）：

1. 会话对象带 `doc` 字段（规范化后的绝对路径），新建会话时写入当前文档路径；
2. 面板打开、每次发送前都会 `checkDocChange()` 比对当前 Typora 文档；
3. 文档变了 → **先找已有同文档且非空的会话**，找到就切过去；没有才把当前空会话改绑，或新建；
4. 纯新建的空会话会被复用（不留一堆「新对话」垃圾）；
5. 关闭 `autoDocSession` 开关后回到旧的单会话连续对话模式。

> 注意顺序：必须「先查已有会话，再考虑改绑空会话」。反过来写会把上一篇的空会话抢走，
> 导致切回原文件时找不到原会话（v2.9.0 开发过程中真实踩过）。

## 3. 流式输出与阅读

### 3.1 合批渲染
`paintStream` 按 60ms 合批；收尾必须 `flushStream` 兜底，否则最后几十毫秒的增量会丢。
换渲染目标（新回答 / 新步骤）时立即画，不排队。

### 3.2 滚动锚定
```
距底距离 < 56px  → 视为「在底部」，新内容到达时保持贴底
否则              → 视为「在读旧内容」，绝不改动 scrollTop，只点亮「回到底部」
```
这是「能边生成边读」的关键。旧实现每个 delta 都 `scrollTop = scrollHeight`，长回答根本没法读。

### 3.3 停止
- 生成中按 `Esc` 或点停止按钮 → 立即中断请求；
- 已生成部分**保留**，消息上标「已停止」；
- 停止后底栏出现「继续」，从断点接着写，而不是重来一遍。

### 3.4 空闲看门狗
`request()` 里对每个数据块重新计时，**60 秒没有任何新数据**才判失败，报「响应中断」而不
是无限转圈。旧的固定总超时会把「输出很长但一直在吐字」的正常请求误杀。

## 4. 消息级操作

| 操作 | 行为 |
|------|------|
| 复制 | 取该条消息的 Markdown 原文（不是 HTML 文本） |
| 编辑重发 | 用户消息就地变输入框，`Enter` 提交 / `Esc` 取消；提交后**切掉该条之后的全部回答**重新问 |
| 重新生成 | 从该条用户消息开始重跑，后续回答一并作废 |
| 继续 | 仅对「已停止」或截断的回答出现 |

编辑重发后必须 `renderChat()` 整列表重排，否则数据已经裁掉、DOM 还挂着旧回答。

---

## 5. Agent 过程可视化

- 计划 2~6 步；每步一张卡，**完成后折叠**，只留标题和结果摘要，避免长任务把界面撑爆；
- 任务上限：`AGENT_MAX_STEPS=6` 步、`AGENT_MAX_TURNS=5` 轮/步、`AGENT_MAX_CALLS=24` 次调用（护钱包）；
- 中途停止：已完成的步骤保留，正在跑的步骤标 `stop`；`status='stopped'` 落盘到会话，
  重开 Typora 后可以「继续」断点续跑；
- 崩溃兜底：`loadSessions` 会把残留的 `status:'running'` 归一为 `stopped`，否则界面永远卡在「运行中」且没有继续按钮。

## 6. 键盘与手势

| 键 / 手势 | 作用 |
|-----------|------|
| `Ctrl+Alt+K` | 开关面板 |
| `Ctrl+Alt+B` | 收起 / 展开会话栏 |
| `Enter` | 发送（输入法组字中不触发） |
| `Shift+Enter` | 换行 |
| `↑`（输入框为空） | 把上一条用户消息拉回输入框编辑 |
| `Esc` | 分层：浮窗 → 模型下拉 → 配置面板 → **停止生成** → 收会话栏 → 关面板 |
| 双击会话标题 | 重命名 |
| 面板外点击 | 按设置项 `closeOnOutside` 决定是否收起 |

`Esc` 的分层顺序是有意为之：生成中按 `Esc` 的直觉是「别写了」，而不是「把界面关掉」。

## 7. 三个原始缺陷的对照

| 原始缺陷 | v2.9.0 |
|---------|--------|
| 没有快捷关闭侧栏的方式 | `Ctrl+Alt+B`、折叠按钮、`Esc` 分层、面板外点击（可选） |
| 生成中只能干等，看不到已生成内容 | 60ms 合批 + 滚动锚定 + 「回到底部」+ 停止保留半成品 + 继续 |
| 换 md 文件仍沿用旧对话上下文 | 会话绑定文档，切文件自动切会话 |

## 8. 兼容红线（Chromium 59）

改交互时不得使用：

- CSS：`inset` 简写、flex 容器的 `gap`、grid 的 `gap` 简写（用 `grid-gap`）、`:focus-within`、
  `backdrop-filter`、`aspect-ratio`、`content-visibility`；
- JS：箭头函数、可选链 `?.`、空值合并 `??`、对象展开、`Object.fromEntries`、`.flat()`。

提交前必跑：

```bash
node scripts/compat-check.js      # 致命项会非 0 退出
node scripts/xss-probe.js         # 必须 0 风险
node scripts/test-agent-protocol.js
node scripts/mock_server.js       # 另开一个终端起测试台
node scripts/ui-check.js          # 真实浏览器行为回归（需本机 Edge）
```
